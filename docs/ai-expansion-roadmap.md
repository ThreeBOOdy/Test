# AI 扩展路线图（修订版）：从刷题系统到“高效备考助手”

> 对齐业务（2026-08）｜对象：「波段研习 · 知练无线电题库」（zhixue-practice）
> 业务定位：少儿编程教培机构，面向无线电证书考试；课堂以题讲知识点，刷题是课堂内容的核心。
> 核心目标：让学生掌握官方题库中的知识点，并刷得足够熟练，最终顺利通过证书考试。

## 0. 一句话结论

本项目的 AI 拓展方向不是“AI 新题、通联陪练、公开题库、深度电路图多模态”，而是：

> **用 AI 帮助学生更高效地刷题、更深刻地理解知识点、更合理地安排复习，从而提高证书通过率。**

核心资产是：**官方原题 + 细粒度答题行为 + 知识点树 + 错题闭环 + 教师审核体系**。
AI 的角色是“刷题教练 / 复习规划师 / 学情分析师”，不是“出题者”。

---

## 1. 业务边界：做什么与不做什么

### 明确不做 / 不优先做

| 原路线图方向 | 结论 | 原因 |
| --- | --- | --- |
| 通联口语陪练 Agent | 暂不做，可作后续拓展 | 机构只负责证书考试知识教学，课堂核心是刷题讲知识点，不涉及真实通联 |
| AI 出题 | 不做 | 证书考官方题库原题，目标是熟练原题，不需要 AI 新题 |
| 电路图多模态深度讲解 | 不做 | 大部分题目为纯文字单选/多选；少量图片仅作做题参考，不涉及细碎电路知识 |
| 题库公开 / MCP 开放 | 不做 | 题库不公开，属于内部教学资产 |
| 语音模拟考官 | 暂缓 | 现阶段不是提分核心，可作为远期演示功能 |
| 多 Agent 审题链 | 不做 | 没有 AI 出题，就不需要审题链 |

### 应该聚焦的方向

1. **AI 解析**：让每道官方题有清晰、准确、面向考试的知识点讲解。
2. **AI 答疑**：学生刷题卡住时，用 AI 引导理解，而不是直接给答案或让老师重复讲。
3. **AI 复习规划**：根据错题和掌握情况，自动安排“今天该刷哪些题 / 该复习哪些知识点”。
4. **学情诊断**：让学生知道哪里弱，让教师知道全班哪里弱、下次课该重点讲什么。
5. **专注与激励**：参考 Forest 等产品，用专注计时、连续打卡、成长反馈提升刷题投入度。
6. **轻度 RPG 游戏化养成**：参考 Habitica，把“刷题、复习、错题清零、专注”变成可成长的游戏化学习计划，提升长期坚持度。

## 2. 目标与成功指标

### 用户目标

| 用户 | 目标 |
| --- | --- |
| 学生 | 高效刷题、理解知识点、减少盲目重复、坚持复习、通过考试 |
| 教师 | 快速定位班级薄弱点，课堂讲题更有针对性，减少重复答疑 |
| 机构 | 提高证书通过率，提升教学效果和续课口碑 |

### 可量化指标

- 证书通过率。
- 错题掌握率 / 三刷完成率。
- 学生每周刷题量、专注时长、连续打卡天数。
- AI 解析查看率、AI 答疑使用率、反馈好评率。
- 教师端班级薄弱点报告的使用率。
- 复习计划完成率。

## 3. 现有可复用资产

| 资产 | 源码位置 | 对 AI 的价值 |
| --- | --- | --- |
| 题库 + 树形知识点 | `Question`、`KnowledgePoint`（prisma/schema.prisma） | AI 解析、复习规划、学情报告的基础 |
| 官方原题及答案 | `Question` 的 stem/options/correctOptionIds | 保证 AI 讲解围绕原题，不偏离考试 |
| 题目图片（少量参考图） | `QuestionImage`、app/api/v1/question-images | 讲题时可把图片作为上下文传给学生查看，不需要深度多模态 |
| 答题行为明细 | `PracticeAnswer`（对错、时间戳、幂等键） | 个性化诊断、复习优先级 |
| 错题三刷闭环 | `WrongQuestion`、lib/domain/wrong-question-mastery.ts | 升级为智能复习队列的基础 |
| 学情统计 | lib/server/learning-statistics-service.ts | AI 报告的结构化数据源 |
| 导入预检 / 审核流 | `ImportBatch` / `ImportBatchRow`、components/import-preview.tsx | 可复用于 AI 解析的教师审核批次 |
| 题目修订 / 审计 | `QuestionRevision`、lib/server/question-revisions.ts | AI 修改解析有据可查、可回滚 |
| 异步 worker | scripts/exam-settlement-worker.ts | AI 批量生成解析的 worker 模板 |
| 角色权限 | STUDENT/TEACHER/ADMIN 严格分离 | 学生 AI 只能访问自己的学习数据 |
| 人物身份目录 | lib/domain/radio-person-catalog.ts | 可选用于激励 / 人格化学习反馈 |

**关键缺口**：`Question` 没有解析字段。Word 导入时“解析：”只留在 `ImportBatchRow.payload` 供追溯，不参与写库。因此 **AI 第一落点仍然是补解析**，但目标是“帮助理解官方题”，不是“生成新题”。

**部署约束与网络方案**：
- 教室内网部署要求无公网端口映射，**连接该服务器的电脑不需要连外网**。
- 如果机构服务器本身可以访问外网，**推荐采用“服务器出网调用云 LLM API”**：客户端只访问内网服务器，由服务器统一请求 DeepSeek / Qwen / GLM / Kimi，客户端完全不接触外网。
- 如果服务器不能访问外网，或希望零 API 费用，再考虑内网 Ollama / vLLM 本地模型。
- 代码层仍保留**模型网关抽象**：`AI_PROVIDER=cloud|ollama`，同一套代码两种模式，后续可随时切换。

**Ollama 部署配置参考**：
- 7B 量化模型（如 qwen2.5:7b-q4）：模型约 4~5 GB，建议服务器至少 16 GB 内存；纯 CPU 可运行但生成较慢，适合夜间批量解析。
- 14B 量化模型：模型约 9~10 GB，建议 32 GB 内存；若要实时答疑体验更好，建议有 NVIDIA 显卡（8 GB 以上显存）或使用云 API。
- 小机构如果没有 GPU 服务器，**优先考虑云 API**；1300~1400 道题批量生成解析用便宜模型成本通常可控，且不占用本地算力。

## 4. AI 功能蓝图

### P0：基础能力（必须先做）

1. **模型网关**
   - 新增 `lib/server/ai/provider.ts`，统一 OpenAI 兼容协议。
   - 支持 `AI_PROVIDER=cloud|ollama`，云侧 DeepSeek / Qwen / GLM / Kimi，内网侧 Ollama。
   - 包含超时、重试、降级、流式、错误标准化。

2. **AI 数据模型与审计**
   - `Question.explanation`：解析内容、版本、审核状态。
   - `AiConversation` / `AiMessage`：学生答疑会话。
   - `ReviewPlan` / `ReviewCard`：复习规划与卡片。
   - `FocusSession` / `StudyStreak`：专注计时与打卡（可选）。
   - `AiUsageLog`：token、模型、耗时、用户，接 `AuditLog` 思路。

### P1：核心备考功能（重点投入）

#### 1. AI 解析生成与展示

- 为官方题库批量生成：
  - 一句话解析：为什么选这个答案。
  - 知识点讲解：对应 `KnowledgePoint` 的核心概念。
  - 记忆点 / 口诀：适合无线电法规、频率、字母解释法等记忆型内容。
- 写回 `Question.explanation`。
- 支持教师审核：AI 生成 → 教师确认/修改 → 发布。
- 学生端做题后可以查看解析，答错时优先展示。

> 这是最直接补齐产品短板的功能，也是 AI 答疑和复习规划的内容基础。

#### 2. AI 答疑教练（轻量 Socratic）

- 学生答错后点“问 AI”。
- AI 结合：本题 + 标准答案 + 知识点 + 该生历史错题。
- 交互方式：
  - 先给提示，引导学生自己想到答案。
  - 如果学生仍然不会，再给出完整解析。
- 图片题：把题目图片作为“参考图”展示，AI 以文字讲解为主，不做深度电路图多模态分析。
- 所有回答标注“AI 生成，仅供参考”，并提供“有帮助 / 没帮助”反馈。

#### 3. AI 复习规划

- 基于：
  - `WrongQuestion` 错题数据。
  - `PracticeAnswer` 最近正确率。
  - 知识点薄弱度。
- 输出：
  - 每日刷题计划：今天优先刷哪些知识点 / 哪些错题。
  - 考前冲刺计划：按距离考试时间倒排。
  - 复习队列：已掌握的降低频率，未掌握的优先出现。
- 可与现有“错题三刷”并存：
  - 保留三刷保底规则。
  - 后续可升级为 FSRS 自适应间隔重复。

#### 4. 学情诊断报告

- 学生端：
  - 本周刷题量、正确率、薄弱知识点 TOP。
  - 下一步建议：该重点练哪个知识点、该复习哪些错题。
  - 鼓励性总结，避免制造焦虑。
- 教师端：
  - 班级整体掌握情况。
  - 哪些知识点全班正确率低，建议下次课堂重点讲。
  - 哪些学生需要重点关注。

#### 5. 专注与激励（参考 Forest）

- 刷题专注模式：
  - 开始一次“专注刷题”，设定目标题量或时长。
  - 完成后获得成就 / 成长记录。
  - 可结合现有无线电主题视觉，做成“信号 / 频段 / 设备”风格。
- 连续打卡：
  - 每日刷题、完成复习计划、错题清零等行为产生 streak。
- 轻量 AI 反馈：
  - 每周生成一句个性化鼓励 / 总结。
  - 可复用 120 位无线电人物做“人物徽章 / 人格化鼓励”，但先不做复杂人格 Agent。

#### 6. 轻度 RPG 游戏化养成（参考 Habitica / Forest）

- **目标**：把“刷题、复习、错题清零、专注”变成有成长感的游戏化学习计划，提升长期坚持度。
- **核心循环**：
  - 完成练习 / 复习计划 → 获得经验值（XP）。
  - 经验值升级 → 解锁称号、头像框、主题皮肤。
  - 每日任务 / 每周任务 → 对应“刷题、复习、错题、专注”四类习惯。
- **学习地图**：
  - 把知识点树变成“地图 / 技能树”，掌握一个知识点就点亮一个节点。
  - 薄弱知识点显示为“待攻克区域”，完成专项练习后点亮。
- **Boss 战 / 副本**：
  - 把“薄弱知识点专项练习”包装成副本。
  - 把“模拟考试”包装成 Boss 战，按正确率对 Boss 造成伤害。
  - 考前冲刺计划 = 限时活动 / 赛季。
- **轻量社交**：
  - 班级排行榜、小队共同完成“班级 Boss”（可选，注意避免过度竞争）。
- **与 AI 结合**：
  - AI 根据薄弱点自动生成“今日任务”和“本周副本”。
  - AI 在升级 / 通关时生成个性化鼓励语。
  - 120 位无线电人物可作为 NPC / 导师，但先不做复杂人格 Agent。
- **克制原则**：
  - 不做抽卡、不做付费、不做复杂装备数值。
  - 游戏化必须服务于“刷题 + 复习 + 通过考试”，不能让学生为了游戏而忽略学习。

### P2：增强功能（可选，视数据和反馈再决定）

- **FSRS 自适应复习**：完整建模记忆曲线，替代固定三刷。
- **错题知识点卡片**：按知识点聚合错题，生成“考前速记卡”。
- **教师 AI 备课**：根据班级薄弱点，生成课堂讲题顺序和重点提示（不生成新题）。
- **语义搜题**：教师/学生用自然语言找题（“关于中继台频率的题”）。
- **人格化教练**：用 120 位无线电人物做讲解风格 / 激励人格，需先设计清楚使用场景。
- **通联口语陪练**：作为远期拓展，等证书考试业务稳定后再评估。

## 5. 架构建议

- **模型网关**：`lib/server/ai/provider.ts`，OpenAI 兼容协议 + 流式。
- **流式输出**：`app/api/v1/ai/chat/route.ts` 使用 SSE；现有 `authenticated-fetch` 扩展流式消费。
- **异步批量**：仿 `exam-settlement-worker` 增加 `ai-batch-worker`，用于批量生成解析。
- **数据模型增量**：
  - `Question.explanation`、`explanationVersion`、`explanationStatus`。
  - `AiConversation` / `AiMessage`。
  - `ReviewPlan` / `ReviewCard`。
  - `FocusSession` / `StudyStreak`。
  - `PlayerProfile` / `PlayerLevel` / `QuestLog`：RPG 等级、经验、每日任务、成就。
  - `AiUsageLog`。
- **隐私与合规**：
  - 身份证号 / 手机号绝不进入 prompt。
  - AI 上下文只送“本题 + 知识点 + 该生本题统计”。
  - AI 调用写审计日志。
  - 提示词注入防护：学生输入作为数据区隔离。
- **成本控制**：
  - 解析批量生成用便宜模型 + 结果缓存，同题只生成一次。
  - 答疑用较强模型按需计费。
  - 内网 Ollama 零边际成本。
- **降级策略**：
  - AI 不可用时，系统仍可正常刷题。
  - 解析为空时展示“暂无解析”，不影响练习主流程。

## 6. MVP 路线（每迭代可独立验收）

### M1：AI 解析 + 答疑 + 模型网关

- `Question.explanation` 字段。
- `ai-batch-worker` 批量生成解析。
- 教师审核解析。
- 学生端查看解析。
- 学生答错后“问 AI”基础答疑。
- 模型网关（云 / Ollama 双模式）。

**验收**：
- 题库解析覆盖率达标。
- 教师审核通过率可统计。
- AI 答疑可用、有反馈入口。
- AI 不可用时刷题主流程不受影响。

### M2：复习规划 + 学情报告 + 轻度 RPG 游戏化

- 每日复习计划 / 考前冲刺计划。
- 学生周报、教师班级薄弱点报告。
- 专注刷题模式 + 连续打卡。
- 经验 / 等级 / 每日任务 / 知识点点亮 / 副本与 Boss 战。
- 轻量 AI 鼓励总结。

**验收**：
- 学生能按计划进入对应练习。
- 教师能看到班级薄弱知识点。
- 专注数据、等级、任务完成情况有留存和展示。
- 游戏化不干扰刷题主流程，可一键关闭或隐藏。

### M3：自适应复习与人格化（可选）

- FSRS 或简化自适应队列。
- 错题知识点速记卡。
- 120 位人物人格化激励 / 讲解风格。
- 教师 AI 备课建议。

**验收**：
- 复习计划确实降低重复刷题量。
- 学生 / 教师使用率和满意度可衡量。

### 远期

- 通联口语陪练。
- 语音 / 播客化。
- MCP 开放（若未来需要生态接入再评估）。

## 7. 风险与对策

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| AI 解析出错 | 官方题有标准答案，讲错会误导学生 | 教师审核后发布；AI 内容标注“仅供参考”；保留修订记录 |
| 学生依赖 AI 直接要答案 | 失去“先思考”的学习过程 | 答疑默认先提示后给答案；可限制单日使用次数 |
| 内网模型能力不足 | Ollama 7B/14B 讲解质量可能不稳定 | 云 / 本地双模式；解析用异步批量，答疑可按需切强模型 |
| 成本上升 | 批量生成和答疑消耗 token | 缓存、去重、限流、用量日志 |
| 功能过重 | 教培机构课堂时间有限，复杂功能没人用 | 每个迭代只做一个闭环，优先做解析和复习计划 |
| 数据量不足 | 学生行为数据少时，个性化复习效果有限 | 先用规则 + 统计实现，数据积累后再上 FSRS |
| 激励变成形式 | 打卡/成就可能沦为刷数据 | 激励绑定真实学习行为：完成复习、错题清零、专注时长 |
| 游戏化过度 | 学生沉迷等级/排行榜，忽略学习本身 | 只做轻度 RPG；不搞抽卡/付费/复杂数值；提供关闭游戏化开关 |

## 8. 参考方向

- Forest：专注计时与正向激励。
- Habitica：RPG 化习惯养成、每日任务、等级、副本与团队激励。
- Anki / FSRS：间隔重复与复习计划。
- Khanmigo / Duolingo Max：苏格拉底式答疑与“解释我的答案”。
- 各类 AI 学习报告：将统计数据转成自然语言建议。
- 现有错题三刷、学情统计、导入审核流：作为功能底座。

> 最终原则：**AI 不替代刷题，而是让刷题更聪明、更坚持、更有效。**
