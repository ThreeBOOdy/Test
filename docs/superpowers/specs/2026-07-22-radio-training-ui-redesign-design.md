# 无线电题库训练优先 UI 重设计规格

**日期：** 2026-07-22  
**项目：** 知练 · 分等级与知识点刷题系统  
**方案：** 方案 B · 训练体验重构  
**视觉方向：** 未来通信 · 克制科技  
**主要目标：** 在不改变现有抽题、判题、权限和数据库规则的前提下，提高手机与电脑上的答题效率、连续训练体验和产品完成度。

## 1. 背景与设计目标

当前项目已经具备登录、题库、知识点、抽题规则、练习快照、即时判题、错题和 Excel 导入等完整业务闭环，但视觉风格仍偏通用教育产品，练习页也没有充分利用桌面键盘、题号导航和移动端拇指热区。

本次设计聚焦以下目标：

1. 将产品品牌升级为面向无线电题库的未来通信视觉系统。
2. 将学生练习页变为全站最高优先级的体验模块。
3. 同时支持手机专注答题和电脑高效率训练。
4. 使用 `gpt-image-2` 生成统一的无线电主题美术资源。
5. 保留现有教师业务结构，只做一致性视觉升级和必要的导航修复。
6. 控制动画、资源体积和视觉噪声，保证长时间学习舒适度。

## 2. 明确范围

### 2.1 本阶段包含

- 全局设计令牌、背景、字体层级、颜色、阴影和交互动效。
- 首页、登录页和修改密码页视觉升级。
- 学生首页、历史、错题和练习页重构。
- 教师端壳层和现有管理页面统一换肤。
- 练习恢复时定位第一道未完成题。
- 桌面题号导航和键盘快捷操作。
- 移动端底部固定训练操作区。
- 真实登录用户信息接入 `AppShell`。
- 教师移动端完整导航。
- GPT Image 美术资源生成、落盘和 Next.js 图片优化。
- 新增必要的单元、交互和响应式验证。

### 2.2 本阶段不包含

- 不修改 Prisma Schema。
- 不改变题目随机算法、判题标准、答案不可修改规则或角色权限。
- 不新增正式考试、计时考试、防作弊或试卷发布。
- 不新增复杂错题组卷算法。
- 不引入大型动画框架或重量级图表库。
- 不重构教师端的数据接口和数据库查询，除非视觉组件所需的数据已经存在。

## 3. 视觉系统

### 3.1 品牌气质

视觉关键词为“未来通信、深空信号、克制科技、专业训练”。界面应体现无线电控制台和轨道通信系统的精密感，但不能演变为高亮霓虹游戏界面。

### 3.2 色彩

- 主背景：接近黑色的深炭蓝和深紫蓝。
- 内容表面：带少量紫蓝倾向的深色卡片。
- 主操作：电光蓝到极光紫的受控渐变。
- 品牌辅助：极光紫。
- 信号辅助：低饱和青色。
- 正确状态：高对比信号绿。
- 待复习与警告：琥珀色。
- 错误与危险操作：受控红色，仅用于真实错误状态。

正文、次级文字、边框和禁用状态必须分别建立明确令牌，不允许在页面中散落无语义颜色值。

### 3.3 内容表面

- 卡片允许轻度半透明和边缘高光。
- 不使用大面积强模糊玻璃拟态。
- 题干、答案、表格和表单使用更实的内容表面，以保证对比度。
- 管理端的动效和光晕强度低于首页和学生首页。

### 3.4 排版

- 中文正文使用高可读系统无衬线字体栈，避免依赖在线字体。
- 页面标题使用较紧字距和高字重，但不牺牲中文可读性。
- 频率、分数、进度、等级和统计数字使用等宽或仪表化数字样式。
- 题干字级在手机和桌面分别控制，长题干不得被固定高度截断。

### 3.5 动效

- 常规交互时长为 160–240ms。
- 允许的动画包括选项状态、进度推进、面板切换、轻微信号波纹和页面进入。
- 不使用持续闪烁、大范围视差或答题过程中持续移动的高亮背景。
- 在 `prefers-reduced-motion: reduce` 下关闭粒子、扫描光和非必要位移动画。

## 4. GPT Image 美术资源

### 4.1 生成规则

- 使用 `gpt-image-2`。
- 图片中不生成任何文字、数字、按钮或 Logo。
- 中文内容继续由 HTML 渲染。
- 统一采用深空通信、轨道网络、天线阵列、抽象频谱、精密信号界面的视觉语言。
- 画面保留足够负空间，便于响应式裁切和叠加 UI。
- 避免人物肖像、军事武器、复杂仪表文字和不可读伪字符。

### 4.2 资源清单

资源保存到 `public/art/`：

1. `home-orbital-network`：横版首页主视觉，轨道通信网络和抽象地球信号。
2. `login-antenna-array`：登录页天线阵列与深空通信站。
3. `student-spectrum-cabin`：学生首页低对比训练舱和频谱背景。
4. `empty-no-signal`：无历史、无错题或无可用练习时的失联信号插图。
5. `training-complete-signal`：练习完成后的信号同步完成插图。

### 4.3 Web 使用方式

- 使用 Next.js `Image`。
- 首页主视觉可使用高优先级加载；其他资源默认懒加载。
- 为移动端提供合理的 `sizes`，避免下载桌面大图。
- 图片必须有准确的替代文本；纯装饰图片使用空替代文本。
- 图像不可承担关键信息表达，资源加载失败时页面仍可完整使用。

## 5. 训练页体验

### 5.1 手机端

- 单列专注布局，题干和选项占据主要空间。
- 顶部仅保留练习名称、当前题号和细线频谱进度。
- 提交、下一题等核心操作固定在底部拇指热区。
- 固定操作区必须考虑安全区，并且不能遮挡最后一个选项。
- 多选题显示已选数量，并在达到标准答案数量后阻止继续增加选择。
- 题干和选项区域允许自然滚动，不设破坏可读性的固定高度。

### 5.2 电脑端

- 中央为题目主区域，右侧为紧凑题号导航。
- 题号区区分已答、当前和未答状态。
- 支持方向键移动选项、数字键选择、`Enter` 提交和左右键切题。
- 键盘操作是增强能力，所有流程必须能够通过鼠标完成。
- 页面不显示完整应用侧边栏，降低训练干扰。

### 5.3 恢复与连续训练

- 保留现有服务端练习快照、题目顺序和答案持久化。
- 恢复练习时自动定位第一道未回答题。
- 如果全部题目已经回答，直接进入完成结果页。
- 已提交题目继续保持不可修改。

### 5.4 判题反馈

- 正确答案使用信号绿边框、图标和低强度光晕。
- 错误提交同时标记用户所选错误项和标准答案。
- 不使用遮挡题目的大型模态弹窗。
- 完成结果展示正确率、答对数量、薄弱知识点和错题巩固入口。

## 6. 学生端页面

### 6.1 学生首页

- 第一视觉层级为“继续上次训练”或“开始推荐训练”。
- 等级综合和知识点专项练习使用“通信频道”卡片表达。
- 频道卡片显示等级、知识点、题量和预计训练时长。
- 学习统计、薄弱知识点、错题和近七日趋势放在第二层级。
- 手机端为纵向任务流；桌面端为主任务区加学习状态侧栏。

### 6.2 历史记录

- 区分进行中和已完成练习。
- 进行中练习提供明确的继续入口。
- 支持按状态、等级和知识点进行前端筛选；不在本阶段新增复杂服务端查询。
- 学习时长只对已完成练习或明确有效的进行中时长统计，避免无限增长。

### 6.3 错题页

- 待巩固题目优先，已掌握题目降低视觉权重。
- 使用信号异常视觉语言，但错误信息必须保持传统、清晰和可理解。
- 保留现有再次答对后自动掌握的业务规则。

## 7. 教师端与公开页面

### 7.1 教师端

- 保留题库、知识点、规则、导入和学生管理结构。
- 统一为低动效深色通信控制台风格。
- 表格、筛选器和表单优先考虑密度、对比度和批量浏览效率。
- `AppShell` 显示真实登录用户，不再使用硬编码姓名。
- 手机端提供全部教师功能入口。
- Excel 导入可以使用“信号数据接入”视觉语言，但成功、警告和错误仍使用明确常规文案。

### 7.2 首页

- 首页控制在一屏核心品牌叙事和少量能力说明。
- 主视觉使用 `home-orbital-network`，但学生与教师入口始终明确可见。
- 不增加冗长营销区块。

### 7.3 登录与修改密码

- 桌面登录页采用插画与表单分栏。
- 手机端隐藏或弱化大图，只保留轻量背景。
- 演示账号提示降低视觉权重。
- 修改密码页继承相同身份和安全视觉语言。

## 8. 组件边界

新增或重构以下组件：

- `SignalBackdrop`：频谱、网格、光晕和减少动态效果处理。
- `SpectrumProgress`：训练进度和信号状态。
- `TrainingChannelCard`：练习入口。
- `QuestionNavigator`：桌面题号导航。
- `AnswerOption`：未选、选中、正确、错误和禁用状态。
- `EmptySignalState`：统一空状态。
- `AppShell`：真实用户、完整导航和响应式壳层。
- `Button`、`Card`、`Badge`、`Progress`：基于语义令牌统一重构。

`PracticeRunner` 应拆分为状态协调组件和可复用展示组件，避免继续将题目、答案、导航、结果和所有事件集中在一个文件中。

## 9. 性能、可访问性与安全

- 不引入大型动画或图表依赖。
- 避免因装饰组件造成不必要的客户端 JavaScript。
- 服务端页面继续在服务端获取数据，客户端只接管必要交互。
- 所有焦点状态清晰可见。
- 颜色不是唯一的正确或错误提示方式，必须同时提供图标或文字。
- 交互目标满足移动端触控尺寸。
- 不将标准答案提前传给未提交题目的客户端状态。
- 不改变现有 HTTP-only Cookie 和角色权限边界。

## 10. 测试与验收

### 10.1 自动化测试

- 恢复练习时定位第一道未答题。
- 单选题切换行为。
- 多选题数量限制。
- 已提交题目不可修改。
- 键盘操作与鼠标操作触发相同状态变化。
- `prefers-reduced-motion` 下非必要动画关闭。
- 现有领域测试继续通过。

### 10.2 浏览器验证

- 手机尺寸：窄屏和常见大屏手机。
- 桌面尺寸：常见笔记本和宽屏桌面。
- 长题干、长选项、多选题、错误反馈和练习完成状态。
- 登录、学生端和教师端角色跳转。
- 图片加载失败时的布局稳定性。

### 10.3 完成标准

- 学生可以在手机和电脑完成完整练习流程。
- 页面无横向溢出，固定底栏不遮挡内容。
- 真实用户信息正确显示。
- 教师移动端所有导航入口可达。
- 核心美术资源成功生成并正确使用。
- 单元测试、ESLint、TypeScript 和生产构建通过。
- 不改变现有数据库结构和核心业务结果。

## 11. 实施顺序建议

1. 生成 GPT Image 美术资源并建立资源清单。
2. 建立全局设计令牌和基础 UI 组件。
3. 重构练习状态与新增训练组件。
4. 重构学生首页、历史和错题页。
5. 重构应用壳层和教师端视觉。
6. 升级首页、登录和修改密码页。
7. 增加自动化测试并完成浏览器响应式验证。
