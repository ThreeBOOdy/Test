## 3. 本阶段目标与非目标

### 3.1 目标

1. 严格分离管理员、教师和学生的账号生命周期、页面、API 与服务端能力。
2. 建立可扩展但当前保持单课程的课程/题库隔离边界。
3. 完成适合小学和初中学生的低负担账号、密码、练习与考试体验。
4. 消除可恢复密码、静默覆盖、重复提交、越权查询、即时泄题和浏览器单点计时等风险。
5. 让关键业务、审计、备份、恢复和保留清理形成可验证闭环。

### 3.2 非目标

- 当前不建设班级模型，也不按班级限制教师数据范围。
- 当前不开发多课程选择、切换或管理界面，只启用 `RADIO` 课程。
- 当前不接入 C++、Python 课程；未来即使接入，也只规划单选和多选知识题，不含在线编程判题。
- 当前不接入 AI 题目解析，不增加解析字段、生成接口或审核流程。
- 当前不生成无线电人物头像；人物头像后续使用独立图像 API 与 `gpt-image-2` 生成时另行实施。
- 当前不讨论超过既定课程边界的后续扩展设计。

## 4. 全局业务不变量

以下规则必须由数据库约束、事务条件或服务端鉴权保证，不能只依赖页面隐藏：

1. 管理员不具备教师教学能力，教师不具备管理员账号管理能力。
2. 教师不能注册，只能由管理员创建。
3. 登录用户名全局唯一、创建或确认后不可修改；真实姓名是独立字段。
4. 学生人物用户名同一时间只能归属一个学生；首次审核通过或导入激活完成后永久不可回收。
5. 每名学生最多存在一个 `IN_PROGRESS` 练习会话。
6. 每个重要业务变更与对应审计日志原子提交；审计失败时业务一起失败。
7. 同一答题或交卷请求可安全重试，不同答案不得覆盖已接受答案。
8. 已进入公共题库的题目永不物理删除。
9. 模拟考试计时、草稿、交卷和判题以服务端状态为准。
10. 敏感原文默认不返回；查看原文必须重新验证并审计。

## 5. 角色与权限边界

### 5.1 管理员

管理员只负责系统和账号管理，包括：

- 创建、停用和重置教师账号。
- 审核学生自主注册。
- 管理学生账号状态、有效期和一次性激活码。
- Excel 导入学生账号。
- 在重新验证后查看学生敏感原文。
- 查看账号、审核、敏感访问、备份和高风险操作审计。

管理员不负责题目、题库导入、练习规则、考试规则或教学统计。

### 5.2 教师

教师只负责教学能力，包括：

- 查看公共题库并创建、修改、停用或归档题目。
- 导入题目并管理本人创建的导入批次。
- 配置练习规则和模拟考试规则。
- 查看全部学生的学习统计，但不能查看账号敏感资料。

教师不能审核学生注册、管理账号、查看敏感原文或管理其他教师的导入批次。

已提交题目属于课程公共题库，不属于单个教师私有数据。所有教师可按权限查看和修订公共题目，修订必须保留版本、审计并执行并发检查。

### 5.3 学生

学生只访问本人的资料状态、练习、考试、历史和错题数据。学生不能查看他人账号、答题记录或人物选择状态详情。

### 5.4 页面和 API 分离

- 管理员页面仅位于 `/admin/*`，管理员 API 仅位于 `/api/v1/admin/*`。
- 教师页面仅位于 `/teacher/*`，教师 API 仅位于 `/api/v1/teacher/*`。
- 学生业务 API 使用学生专属或明确的公共命名空间。
- 删除 `requireTeachingUser()` 这类跨角色能力聚合；每条路由必须调用单一角色守卫。
- 页面入口、路由守卫、服务层查询条件和数据库写入条件必须同时落实角色隔离。

## 6. 管理员与教师账号生命周期

### 6.1 教师创建

- 教师不能自主注册，只能由管理员创建。
- 创建时填写不可变登录用户名与独立真实姓名。
- 系统生成随机临时密码，首次登录必须修改。
- 临时密码不做可逆保存；如需要交付，只能在创建结果中展示一次。

### 6.2 教师状态

- 教师账号可以启用或停用，不允许物理删除。
- 登录用户名创建后不可修改。
- 停用教师会立即撤销其全部服务端会话。
- 教师停用不影响其已提交到公共题库的题目、修订历史和审计记录。
- 教师只能管理本人导入批次；停用后批次仍保留供审计。

### 6.3 管理员账号

- 管理员与教师是完全不同的账号和角色，管理员账号不能再兼任教师。
- 现有测试账号中 `teacher` 实际为 `ADMIN`、`instructor` 才是 `TEACHER` 的混淆必须消除。
- 演示与种子数据应使用明确命名，并分别验证管理员和教师入口。

## 7. 学生用户名、实名资料与人物身份

### 7.1 字段分离

- `username`：登录用户名，全局唯一，不可修改。
- `realName`：学生真实姓名，可由管理员按受控流程修改。
- 身份证号和手机号继续收集并加密管理，不参与登录用户名生成。
- 管理员列表同时显示真实姓名和已选择用户名，但不能替学生修改用户名。

### 7.2 无线电人物身份目录

系统建立无线电领域贡献人物目录，数量覆盖预计不超过 100 名学生并保留充足余量。每个人物至少包含稳定内部 ID、唯一用户名、人物姓名、性格特点、代表事迹、贡献简介、头像资源状态和是否可选状态。

目录可以包含科学家、工程师、发明者、重要获奖者及其他有明确无线电贡献的人物，但具体名单和史实内容需在后续内容建设中校订。

### 7.3 学生选择流程

- 自主注册学生先填写实名基础资料，再进入独立页面选择人物用户名。
- Excel 导入学生首次激活后进入人物选择页面。
- 页面展示人物头像、性格特点和主要事迹，降低低龄学生选择负担。
- 学生确认前可以返回和更换；确认后立即占用该人物身份。
- 同一人物身份不能被两个学生确认。
- 管理员不能代选、替换或修改学生的人物用户名。

### 7.4 占用与永久绑定

- 选择确认必须使用数据库条件写入，避免两名学生并发抢占同一人物。
- 自主注册学生确认后进入占用状态，在待审核、拒绝和重新提交过程中继续绑定该账号。
- 自主注册账号首次审核通过后，该人物身份永久不可回收。
- Excel 导入账号在激活完成时视为管理员创建完成，该人物身份永久绑定。
- 停用账号、密码重置、长期不使用或学生毕业均不释放已永久绑定的人物身份。

## 8. 学生自主注册与管理员审核

### 8.1 注册入口

- 学生仍可在教室内网自主提交注册申请。
- 不使用学校注册码或 CAPTCHA，访问边界由指定内网 IP、防火墙和内部 HTTPS 保证。
- 注册流程分为实名资料填写和人物用户名选择两个步骤。
- 未完成全部步骤前不得提交审核。

### 8.2 审核权限

- 只有管理员可以查看、通过、拒绝和批量处理学生注册。
- 删除教师注册审核页面、导航入口、API 权限和服务端兼容能力。
- 教师不能通过直接调用管理员 API 绕过页面限制。

### 8.3 服务端分页和筛选

- 注册审核列表使用服务端分页、搜索和筛选。
- 默认每页 20 条，最大每页 100 条。
- 搜索、状态筛选、来源筛选、日期筛选和排序都在服务端执行。
- 响应返回 `page`、`pageSize`、`total` 和 `totalPages`。

### 8.4 批量审核原子性

- 批量通过或批量拒绝采用全部成功或全部失败语义。
- 服务端先验证全部目标的存在性、当前状态、人物占用、有效期和版本。
- 任意一项不满足条件时，整个事务回滚，不允许部分成功。
- 每个学生审核历史、账号状态变化和批量操作审计在同一事务中写入。

## 9. 学生 Excel 导入与一次性激活

### 9.1 导入限制

- 单次最多 200 行学生数据。
- 单个文件最多 10 个工作表。
- 所有工作表统一解析，但保留工作表名和原始行号。
- 超限文件在预检阶段直接拒绝，不截断后静默继续。

### 9.2 预检

- 预检结果存储在服务端，并使用服务端分页、搜索和错误筛选。
- 页面只加载当前页，不将全部行一次发送到浏览器。
- 行编辑后由服务端重新校验，并更新批次统计。
- 批次提交前重新执行完整校验，防止预检后的数据或外部状态变化。

### 9.3 初始密码

- Excel 中的初始密码只在请求解析期间短暂存在。
- 进入持久化前立即按学生密码算法生成不可逆哈希。
- 数据库、预检 JSON、审计、错误报告、日志和导出均不得保存可解密密码或明文密码。
- 导入草稿过期时立即清除初始密码哈希，草稿在 7 天后删除。

### 9.4 激活流程

- 提交导入后创建 `ACTIVATION_REQUIRED` 学生账号。
- 学生使用“初始密码＋一次性激活码”进入受限初始化会话，而不是直接获得完整学生权限。
- 初始化必须完成新密码设置和人物用户名选择。
- 完成后激活码立即失效，账号进入完整学生状态。
- 初始化未完成时不能开始练习、查看题库答案或进入普通学生工作台。

### 9.5 激活码安全

- 激活码使用高熵随机值，数据库只保存哈希。
- 激活码默认有效期 30 天。
- 激活码只在导入提交或重新生成结果中展示一次，之后不可恢复。
- 遗失或过期只能由管理员重新生成；新码生成时旧码立即失效。
- 重新生成激活码属于高风险操作，要求 5 分钟内管理员重新验证并写入审计。

### 9.6 导入提交

- 学生导入提交采用单一事务，任意行失败时全部回滚。
- 账号、敏感字段加密值、密码哈希、激活码哈希、导入结果和审计日志原子提交。
- 提交结果不得再次返回初始密码，只返回一次性激活码及必要的非敏感交付信息。

## 10. 学生账号管理、密码与敏感资料

### 10.1 学生账号列表

- 学生账号管理使用服务端分页、搜索和筛选。
- 默认每页 20 条，最大每页 100 条。
- 可按账号状态、来源、年级、有效期和人物用户名状态筛选。
- 默认列表只返回业务所需的脱敏数据，不返回完整身份证号或手机号。

### 10.2 分角色密码规则

- 学生密码至少 8 位。
- 教师和管理员密码至少 12 位。
- 所有角色均不强制大写、小写、数字和符号组合。
- 允许适合学生记忆的长口令，但禁止使用已知极弱默认值和与用户名完全相同的密码。
- 密码重置后必须强制首次登录修改，并立即撤销该账号全部现有会话。
- 当前界面中“密码至少 6 位”的提示和校验必须按角色替换。

### 10.3 敏感信息显示

- 身份证号和手机号默认脱敏展示。
- 管理员修改敏感资料时直接输入新值，不要求先读取旧原文。
- 查看敏感原文必须在 5 分钟内重新验证管理员密码。
- 每次查看按具体字段记录访问审计，包括操作者、学生、字段、时间和原因。
- 教师和学生端永远不提供敏感原文读取接口。

### 10.4 高风险管理员操作

以下操作必须具有 5 分钟内有效的管理员再次验证状态：

- 查看身份证号或手机号原文。
- 重置学生、教师或管理员密码。
- 重新生成或重发一次性激活码。
- 启用或停用学生、教师或管理员账号。
- 批量通过或拒绝学生注册。
- 修改账号有效期或长期有效状态。
- 其他后续被标记为同等级风险的账号与密钥管理操作。

再次验证状态绑定当前管理员服务端会话，不跨会话共享；退出、改密或会话撤销后立即失效。

## 11. 敏感数据加密与密钥管理

### 11.1 应用层加密

- 身份证号、手机号等需取回原文的字段使用认证加密保存。
- 每条密文保存密钥 ID、随机 nonce/IV、密文和认证标签；不在数据库中保存主密钥。
- 用独立的 keyed hash 支持精确重复检查，不能用该哈希还原原文。
- 不允许复用登录密码密钥、会话密钥和敏感数据加密密钥。

### 11.2 密钥轮换

- 当前密钥只用于新写入和重新加密。
- 旧密钥保留只读解密能力，直到所有相关数据完成轮换并经过验证。
- 记录明确的密钥 ID，不通过“尝试所有密钥”猜测解密。
- 密钥轮换仅通过服务器脚本或运维命令执行，不提供 Web 页面。
- 轮换脚本必须支持分批、可重试、审计和完成校验。
- 密钥材料通过服务器秘密管理或受控环境变量提供，不进入仓库、镜像、日志或备份明文。

## 12. 数据库有状态会话

### 12.1 会话模型

- 浏览器 Cookie 只保存高熵随机会话令牌。
- 数据库只保存令牌哈希、用户 ID、角色、创建时间、最后活动时间、绝对到期时间和撤销时间。
- Cookie 不设置持久化 `Max-Age` 或 `Expires`，关闭浏览器后客户端会话失效。
- 服务端每次请求验证数据库会话状态、账号状态、空闲时限和绝对时限。
- 退出登录时服务端立即撤销会话，而不只是清除 Cookie。

### 12.2 分角色时限

- 学生：连续无操作 1 小时退出；浏览器关闭后会话失效。
- 教师：空闲 2 小时，最长 8 小时。
- 管理员：空闲 30 分钟，最长 4 小时。
- 所有角色均不提供“记住登录”。
- 空闲时间按受认证业务请求更新；静态资源和无意义轮询不延长会话。

### 12.3 强制撤销

以下事件发生后，服务端立即撤销该用户全部会话：

- 主动退出。
- 修改密码。
- 管理员重置密码。
- 账号被停用、过期或权限角色发生变化。
- 管理员主动执行“退出所有设备”。

## 13. 内网部署与 HTTPS

### 13.1 网络边界

- 系统部署在自有服务器，仅绑定指定教室内网 IP。
- 防火墙只允许受控内网网段访问 HTTPS 端口。
- 数据库、应用内部端口和 worker 管理端口不对学生网段公开。
- 不依赖“地址难猜”作为访问控制，网络绑定和防火墙规则必须明确配置。

### 13.2 内部 CA HTTPS

- 使用 Caddy 内部 CA 为内网 IP 提供 HTTPS。
- 教室设备预装并信任内部根证书。
- 学生通过 `https://<内网 IP>` 访问，不使用明文 HTTP 登录。
- HTTP 仅用于重定向到 HTTPS，或由防火墙完全关闭。
- 当前生产配置中的公网域名假设、`80/443` 全网卡暴露和外部证书流程必须调整为内网模式。

## 14. 课程与题库隔离边界

### 14.1 `Course` 模型

- 立即增加课程实体，当前仅种子化并启用 `RADIO`。
- `Course` 至少包含稳定代码、名称、启用状态、创建时间和更新时间。
- 等级、知识点、题目、题库导入批次、练习规则、模拟考试规则和练习会话都必须直接或通过不可歧义关系归属课程。
- 所有唯一键和查询条件必须包含课程边界，例如题目身份键为 `courseId + levelId + externalQuestionCode`。
- 当前页面不展示课程选择器，服务端使用唯一启用课程或明确配置的 `RADIO` 课程。

### 14.2 当前题型边界

- 当前及已规划课程只支持 `SINGLE_CHOICE` 和 `MULTIPLE_CHOICE`。
- 不设计代码提交、编译沙箱、测试用例、部分分、题目运行时或 OJ 判题模型。

## 15. 题目生命周期与修订

### 15.1 公共题库

- 教师导入批次仅由创建教师管理。
- 批次提交后产生的题目属于 `RADIO` 公共题库。
- 其他教师可以查看和按权限修订公共题目，但不能修改或撤销原教师的导入批次记录。

### 15.2 不物理删除

- 已提交到公共题库的题目永不物理删除。
- `ACTIVE`：可进入新练习。
- `DISABLED`：暂时停用，可修正后重新启用。
- `ARCHIVED`：永久退出日常使用，但保留查询、历史和审计。
- 导入批次撤销时统一归档该批次已提交题目，不再删除“尚未被使用”的题目。
- 只有尚未提交的导入草稿及其行数据可以按保留规则物理删除。

### 15.3 修订历史

- 修改题干、选项、正确答案、等级、知识点、题型、状态或选项顺序锁定规则时生成完整题目修订版本。
- 修订记录包含题目完整内容快照、版本号、操作者、变更时间和来源动作。
- 恢复旧版本会创建一个新的当前版本，不覆盖或删除历史版本。
- 被发现答案错误的题目应立即停用，完成修正后再启用。
- 已完成练习使用会话快照，不因后续题目修订自动重算历史结果。

### 15.4 乐观并发

- 题目、知识点和练习/考试规则更新必须提交客户端读取到的 `updatedAt` 或等价版本值。
- 服务端更新条件同时匹配 ID 和版本；不匹配时返回 `409 Conflict`。
- 冲突时返回当前版本摘要，要求操作者重新载入和确认，不允许静默覆盖。
- 即使现实中通常只有一人编辑，也不降低该一致性要求。

## 16. 题库 Excel 导入与重复识别

### 16.1 批次所有权和预检

- 教师只能查看、编辑、提交、撤销本人创建的题库导入批次。
- 多工作表解析保留 `sheetName` 和工作表内原始行号。
- 预检、行编辑、提交和重复判断使用同一份服务端快照。
- 批次提交仍采用全部成功或全部失败的事务语义。

### 16.2 重复身份键

- 有外部题目编号时，身份键为 `课程 + 等级 + 外部题目编号`。
- 同一 Excel 批次内出现重复身份键时，预检直接报错。
- 与公共题库已有题目完全一致时标记为“已存在”，允许提交但不重复创建。
- 身份键相同但题干、选项、答案、知识点或选项顺序锁定状态不同，标记为“内容冲突”，必须处理后才能提交。
- 题目更新只能通过题库修订流程完成，导入文件不能覆盖现有题目。

### 16.3 无编号题目

- 无外部题目编号时，使用规范化后的题干和选项内容生成稳定指纹。
- 指纹相同或高度相似时标记为疑似重复警告，由教师确认。
- 疑似重复警告本身可允许提交，但教师确认动作必须记录在批次审计中。

### 16.4 提交时复检

- 提交事务内重新查询公共题库并执行重复和冲突检查。
- 预检后若其他教师已提交相同身份键，当前批次按最新状态重新分类。
- 任何未解决内容冲突使整个批次失败。
- 禁止使用 `skipDuplicates` 静默忽略冲突或批次内部重复。

## 17. 选项随机化与顺序锁定

### 17.1 默认规则

- 所有学生练习模式默认随机排列题目选项，不只模拟考试。
- 每次创建新练习时重新随机；同一练习会话内永久冻结。
- 刷新页面、重新登录和历史复盘均使用学生当次实际看到的顺序。
- 页面按随机后的顺序重新标记 `A、B、C……`。
- 正确答案映射必须基于不可变选项身份，不依赖原始显示字母。

### 17.2 保持顺序例外

- 题目增加“保持选项顺序”标记，默认关闭。
- 对“以上都正确”“A 和 B”“前两项”等依赖字母或位置的特殊题目启用该标记。
- 导入预检检测依赖位置的风险文字并产生警告，不自行修改题目或答案。
- 教师必须在提交前确认警告或将该题标记为保持顺序。

### 17.3 判题规则

- 单选题只能选择一个选项。
- 多选题只有选择集合与标准答案集合完全一致才算正确。
- 少选、多选或包含任一错误选项，整题判错。
- 不设计分值、部分得分或题目权重。
- 学生界面不提示“本题应选 X 项”；只通过单选控件与多选控件区分题型。
- `selectionSpec` 可作为导入校验元数据保留，但不向学生展示。

## 18. 练习会话生命周期

### 18.1 唯一进行中练习

- 每名学生只允许一个 `IN_PROGRESS` 练习，包括普通练习和模拟考试。
- 开始新练习前，服务端检查是否存在进行中会话。
- 如存在，学生只能继续旧练习或明确放弃，不能直接创建新会话。
- 该规则必须有数据库可执行的唯一性保证或等价的事务锁定方案，不能只靠先查后建。
- 并发创建请求中只能有一个成功；另一个返回现有会话信息。

### 18.2 会话快照

- 创建会话时冻结题干、选项实际显示顺序、正确答案映射、知识点、等级、题型和规则快照。
- 后续题目修订、停用或归档不改变已创建会话。
- 普通练习已正式提交的答案不可修改。
- 模拟考试在交卷前保存的是可修改草稿，交卷后转为不可修改正式答案。

### 18.3 答题幂等

- 每次普通答题和模拟考试交卷使用客户端生成的幂等请求 ID。
- 同一请求 ID、同一规范化答案重复到达时返回第一次的结果，不重复写入答案、错题和统计。
- 同一请求 ID 携带不同答案时返回冲突，不覆盖原结果。
- 已正式提交题目收到不同请求 ID 的不同答案时同样拒绝覆盖。
- 幂等结果与业务写入在同一事务中提交。

### 18.4 主动放弃

- 放弃前进行二次确认，并明确提示“放弃后不能恢复”。
- 保存 `abandonedAt`、放弃时已答题数和最后题号，保留题目快照及已有正式答案。
- 放弃后状态变为 `ABANDONED`，释放唯一进行中约束。
- 历史页面显示“已放弃”，但不计入累计练习次数、正确率、学习时长或考试通过率。
- 普通练习中已正式提交的错误答案继续保留在错题本；未提交草稿不进入错题本。
- 模拟考试放弃时不批改任何草稿、不更新错题本、不显示答案或正确选项。

## 19. 错题与掌握判定

### 19.1 错题来源

- 普通练习正式提交错误时进入或更新错题本。
- 模拟考试交卷后，回答错误题进入错题本。
- 模拟考试未作答题按错误计分，并以“未作答”原因进入错题本。
- 主动放弃模拟考试不批改，因此不产生任何错题变化。

### 19.2 三刷连续正确

- 错题需要在三个不同练习会话中连续答对 3 次，才标记为已掌握。
- 正确记录可以来自错题巩固、普通练习或模拟考试。
- 同一会话内不能为同一题累计多次正确进度。
- 再次答错或模拟考试未作答时，连续正确进度重置为 `0/3`。
- 主动放弃中的草稿和未正式提交答案不参与判定。
- 已掌握题再次答错时重新变为待巩固，历史错误次数继续累计。
- 学生错题页只显示简单的 `0/3`、`1/3`、`2/3` 巩固进度，不展示复杂算法。

### 19.3 数据记录

错题模型除总错误次数外，应能区分最近错误原因、连续正确次数、最近计数会话、掌握时间和再次失效时间，避免通过重复请求或同一会话刷进度。

## 20. 模拟考试规则

### 20.1 基础规则

- 模拟考试使用服务器计时。
- 学生可以不限次数参加，不设置每日次数或冷却时间。
- 每次考试创建独立试卷快照并重新随机抽题，不复用上一份试卷。
- 不保证连续两次完全无重复题；题库足够时通过随机自然产生差异。
- 每次记录永久保留，学生不能删除。
- 仍遵守每名学生只有一个进行中练习的全局约束。

### 20.2 合格判定

- 不设计分数系统。
- 教师配置单选题数、多选题数、考试时长和合格所需正确题数。
- 每题权重相同，单选和多选均按一题计数。
- 结果显示“答对 X/Y 题、合格”或“答对 X/Y 题、未合格”。
- 可以显示正确率作为学习统计，但不显示“75 分”等分数，也不设置最高分。
- 历史和汇总可显示参加次数、合格次数和最近一次结果。

### 20.3 草稿实时保存

- 交卷或到时前，学生可以反复修改或取消选择。
- 每次修改后自动保存到服务端，并显示“保存中”“已保存”或“保存失败”。
- 刷新、浏览器意外关闭、重新登录或短暂断网后，恢复服务端最后成功保存的答案和当前题号。
- 网络断开期间允许继续选择，但必须明确显示尚未保存；恢复网络后自动重试。
- 到时结算只采用服务端已成功保存的草稿，不依赖浏览器最后一刻尚未上传的数据。

### 20.4 草稿版本冲突

- 草稿保存携带递增版本号或等价的条件版本。
- 延迟到达的旧请求不能覆盖较新的草稿。
- 多标签页发生旧版本写入时返回 `409 Conflict`，要求重新载入，不使用最后写入覆盖。
- 同版本同内容重试返回已保存结果；同版本不同内容拒绝覆盖。

### 20.5 服务器到时交卷

- 部署独立轻量 `worker` 服务，不在 Next.js Web 进程中依赖内存定时器。
- worker 每 15 秒扫描一次已到期且仍为 `IN_PROGRESS` 的模拟考试。
- 通过数据库事务和状态条件抢占结算，多个 worker 也只能成功交卷一次。
- 自动交卷与主动交卷共用同一幂等结算函数。
- 完成时间按考试 `expiresAt` 记录，而不是 worker 实际晚几秒执行的时间。
- 学生重新进入、查询成绩或尝试提交时，也顺带结算已过期考试，作为 worker 异常时的保险。
- worker 停机后恢复会补交全部已过期考试，不暂停或延长考试时间。

### 20.6 到时与未作答

- 网络中断不暂停计时。
- 到时自动交卷时，未作答题按错误处理。
- 未作答题进入错题本，但原因标记为“未作答”，与“回答错误”区分。
- 主动放弃考试不判分，不将所有未答题批量加入错题本。
- 结算来源需区分主动交卷、到时自动交卷和主动放弃。

### 20.7 延迟判题与答案展示

- 考试过程中只显示草稿保存状态，不显示对错、正确答案或解析。
- 主动或到时交卷后立即显示总题数、答对题数和合格状态。
- 交卷后允许逐题查看自己的答案和正确答案。
- 主动放弃后不显示尚未正式结算题目的答案或正确选项。
- 当前不建设题目解析；删除“解析功能将在教师审核后开放”等误导提示。

### 20.8 随机化

- 每次考试随机抽题并随机排列题目顺序。
- 选项按第 17 节规则随机排列，特殊锁定题目保持原顺序。
- 同一场考试创建后，题序和选项顺序永久冻结。
- 教师查看考试记录时按学生当次实际看到的顺序显示。

## 21. 学习历史与统计口径

- `COMPLETED` 会话计入累计练习次数、正确率和学习时长。
- `ABANDONED` 会话在历史中可见，但不进入上述汇总指标。
- `IN_PROGRESS` 会话显示为进行中，不计入完成指标。
- 模拟考试统计区分主动交卷、到时交卷和主动放弃。
- 模拟考试合格率只以已完成考试为分母。
- 教师统计可以查看全部学生的学习数据，但查询响应不得混入身份证、手机号、激活码或账号安全字段。
- 学习时长使用服务端会话起止时间；到时交卷的完成时间为 `expiresAt`。

## 22. 审计与事务边界

### 22.1 原子审计

以下重要操作的业务变化与审计日志必须在同一数据库事务中提交：

- 学生审核、批量审核与拒绝重提。
- 学生和教师创建、启停、密码重置、有效期修改与激活码重发。
- 敏感数据修改和原文查看授权记录。
- 学生导入和题库导入提交、撤销。
- 题目创建、修订、状态变化和版本恢复。
- 知识点及练习/考试规则修改。
- 高风险会话撤销和密钥轮换批次状态变化。

审计写入失败时，业务事务必须回滚。禁止在事务提交后另行“尽力写审计”。

### 22.2 审计内容

- 记录操作者、动作、目标类型、目标 ID、请求关联 ID、时间和必要的前后状态摘要。
- 不记录密码、激活码、会话令牌、身份证原文、手机号原文、加密密钥或完整答卷敏感载荷。
- 批量操作记录批次级审计和每个目标的业务历史，便于追溯全部成功语义。

## 23. 数据保留与每日清理

每日自动执行分级清理，规则如下：

| 数据类型 | 保留规则 |
| --- | --- |
| 登录尝试 | 30 天后删除 |
| 过期且未提交的题库导入草稿 | 过期 7 天后删除 |
| 过期学生导入草稿密码哈希 | 过期时立即清除 |
| 过期且未提交的学生导入草稿 | 过期 7 天后删除 |
| 已提交或已撤销批次的行明细 | 90 天后删除或压缩为批次摘要 |
| 审计日志 | 保留 2 年 |
| 学生审核历史 | 不自动删除 |
| 练习、考试、正式答案和错题 | 不自动删除 |
| 数据库会话 | 到期或撤销后按短期运维窗口清理 |

清理任务必须幂等、分批执行、记录成功和失败摘要，并避免长事务锁住业务表。

## 24. 备份、离线副本与恢复验证

### 24.1 加密备份

- 数据库备份在离开数据库进程后立即加密。
- 备份加密密钥与数据库、应用镜像和备份文件分离保存。
- 备份文件包含时间、数据库版本、应用提交、迁移版本和校验和等清单信息。
- 当前仅输出未加密 SQL 的 `scripts/backup.ps1` 不满足生产要求。

### 24.2 自动保留和清理

- 自动创建日备份，并按明确的日、周、月层级保留。
- 清理依据清单和创建时间执行，不依赖模糊文件名匹配。
- 删除前验证目标路径位于指定备份目录内。
- 备份失败或清理失败必须告警并保留日志。

### 24.3 离线副本

- 至少维护一份不长期挂载在生产服务器上的加密离线副本。
- 离线复制完成后校验文件哈希。
- 备份密钥不能只存在于同一台生产服务器上。

### 24.4 恢复验证

- 定期在隔离环境执行恢复演练。
- 验证数据库可启动、迁移版本一致、关键表数量合理、抽样敏感字段可解密、登录和练习核心链路可运行。
- 记录最近成功恢复时间、使用的备份、耗时、校验结果和发现的问题。
- “备份文件已生成”不等于备份可恢复。

## 25. 目标数据模型增量

本节描述核心增量，具体字段命名可在实施计划中细化：

- `Course`：课程边界，当前仅 `RADIO`。
- `PersonIdentity`：无线电人物身份目录和永久占用状态。
- `User.username` 与 `User.realName` 明确分离，用户名不可变。
- `TeacherAccount` 或等价字段：首次改密、启停和管理员创建来源。
- `ActivationCredential`：一次性激活码哈希、有效期、版本和使用时间。
- `ServerSession`：有状态会话、空闲和绝对到期、撤销状态。
- `AdminReauthentication` 或会话内再次验证时间戳。
- `Question.preserveOptionOrder`。
- `QuestionRevision`：完整题目版本历史。
- `PracticeSession.abandonedAt`、结算来源和课程归属。
- `PracticeExamDraft` 或等价草稿存储：答案、当前题号和版本。
- `PracticeAnswer`：幂等请求关联和未作答原因。
- `WrongQuestion`：连续正确进度、最近计数会话和错误原因。
- `IdempotencyRecord` 或业务表唯一请求键。
- 各关键模型保留 `updatedAt` 或显式版本号用于乐观并发。

## 28. 验收原则

### 28.1 权限验收

- 管理员账号访问任意教师 API 返回 `403`，教师账号访问任意管理员 API 返回 `403`。
- 教师无法通过页面、直接请求或服务层调用审核学生或读取敏感数据。
- 每个题库批次查询和写入都验证教师所有权。

### 28.2 一致性验收

- 批量审核任一目标冲突时无目标发生变化。
- 审计写入故障时重要业务变化全部回滚。
- 并发创建练习时每名学生最多保留一个 `IN_PROGRESS`。
- 并发保存草稿、修改题目和提交答案时不会发生静默覆盖。
- 相同幂等请求重试不重复增加答案、错题、掌握进度或统计。

### 28.3 考试验收

- 关闭浏览器后考试仍按服务器时间到时交卷。
- worker 重启后补交过期考试且只结算一次。
- 考试期间接口不返回正确答案或判题结果。
- 未答题按错误结算并以“未作答”进入错题本。
- 主动放弃不批改、不泄露答案、不计完成统计。

### 28.4 安全验收

- 数据库和备份中搜索不到学生初始密码、激活码明文或会话令牌明文。
- 关闭浏览器后会话 Cookie 失效；退出、改密、停用后旧令牌服务端立即失效。
- 未重新验证的管理员不能查看敏感原文或执行高风险操作。
- 教室设备通过内部 CA HTTPS 访问指定内网 IP，无证书警告。

### 28.5 数据与恢复验收

- 每日清理按保留表执行且可安全重试。
- 已提交题目在撤销批次后仍可审计和用于历史快照，不发生物理删除。
- 加密备份可以在隔离环境恢复，并通过核心登录、题库和练习链路验证。

## 30. 共同理解结论

当前项目仍是一套教室内网使用的无线电选择题练习系统。设计上立即建立课程隔离和可持续的数据边界，但产品界面保持单课程、低复杂度。管理员专注账号和安全，教师专注公共题库和教学，学生使用不可变的无线电人物用户名完成练习。所有关键流程以服务端状态、事务、幂等、审计和可恢复性为核心，不再依赖页面约定、浏览器内存或可逆秘密保存。

本轮审视至此形成完整共同理解。后续如进入实施，应先依据本规格拆分迁移与实施计划，不应直接在现有模型上零散补丁式修改。

## 附录 A：本轮已确认问题与决策清单

1. 学生注册只允许管理员审核，删除教师审核能力。
2. 管理员与教师完全分离，管理员不兼任教学权限。
3. 教师不能自主注册，只能由管理员创建；用户名不可修改，只能停用，不能删除；临时密码首次登录强制修改。
4. 当前不建立班级模型；教师可查看全部学生学习统计，但不能查看账号敏感资料。
5. 当前立即建立课程/题库隔离边界，但不开发多课程界面，只启用 `RADIO`。
6. 未来 C++、Python 课程只规划单选、多选知识题，不包含在线编程判题。
7. 批量注册审核采用全部成功或全部失败的事务语义。
8. 学生账号管理和注册审核都采用服务端分页、搜索和筛选，默认 20、最大 100。
9. 学生导入初始密码全流程只保存不可逆哈希。
10. 登录用户名与真实姓名分离，用户名全局唯一且创建后不可修改。
11. 学生实名资料填写后单独选择无线电贡献人物用户名；导入学生首次登录后选择。
12. 人物目录需要覆盖不超过 100 名学生并保留余量，人物身份不可重复。
13. 人物确认选择后立即占用，自主注册首次审核通过后永久不可回收。
14. Excel 导入学生使用一次性激活码和初始密码进入受限首次登录流程。
15. 激活码只展示一次、不可恢复、默认 30 天；遗失或过期只能重新生成，旧码立即失效并审计。
16. 学生密码至少 8 位，教师和管理员至少 12 位，均不强制复杂字符组合。
17. 不使用学校注册码或 CAPTCHA，由教室内网边界限制访问。
18. 部署使用指定内网 IP、防火墙和内部 HTTPS。
19. 使用 Caddy 内部 CA，并在教室设备预装根证书。
20. 管理员与教师的 API 路径、页面入口和服务端能力全部严格分离。
21. 学生 Excel 单次最多 200 行、最多 10 个工作表，预检结果服务端分页。
22. 重要业务变更和审计日志原子提交，审计失败则业务回滚。
23. 教师只管理本人题库导入批次，已提交题目进入公共题库。
24. 题目、知识点和规则检测版本冲突，返回 `409`，拒绝静默覆盖。
25. 答题和交卷相同请求可安全重试，不同答案禁止覆盖。
26. 学生空闲 1 小时；教师空闲 2 小时、最长 8 小时；管理员空闲 30 分钟、最长 4 小时；均不记住登录。
27. 数据库备份采用加密、自动保留清理、离线副本和定期恢复验证。
28. 临时数据按用途分级保留并每日自动清理。
29. 身份证号和手机号默认脱敏；修改无需先看原文；查看原文必须重新验证并审计。
30. 高风险管理员操作必须具有 5 分钟内有效的再次验证。
31. 敏感数据密钥使用密钥 ID，旧密钥保留只读解密；轮换使用服务器脚本，不提供 Web 功能。
32. 使用数据库有状态会话；退出、改密、停用和重置后服务端立即失效。
33. 每名学生只允许一个进行中练习，开始新练习前必须继续或放弃旧练习。
34. 模拟考试采用服务器计时、答案草稿实时保存、到时自动交卷。
35. 考试过程中不显示对错和正确答案，交卷后再统一展示结果。
36. 考试未作答题按错误计分并进入错题本，原因单独标记为“未作答”。
37. 考试草稿允许修改、断网恢复和自动重试，并使用版本号拒绝旧请求覆盖。
38. 独立 worker 每 15 秒扫描过期考试，自动交卷与主动交卷共用幂等结算事务。
39. 主动放弃练习留档但不计完成统计；考试放弃不批改、不更新错题本、不泄露答案。
40. 错题必须在三个不同练习会话中连续答对 3 次才标记为已掌握。
41. 当前暂不建设题目解析；后续接入 AI 后再设计生成、审核和版本流程。
42. 多选题必须完全匹配标准答案，不设部分得分，不向学生提示应选数量。
43. 系统不设计分数；模拟考试仍按答对题目数量判定合格或未合格。
44. 模拟考试不限重考次数，每次重新抽题并独立永久留档。
45. 模拟考试打乱题目和选项顺序，同一会话内顺序冻结。
46. 所有练习模式默认打乱选项；特殊题可锁定顺序，导入时提示依赖字母或位置的风险。
47. 已进入公共题库的题目永不物理删除，只能停用或归档，并保留完整修订历史。
48. 题库导入区分完全相同、内容冲突和无编号疑似重复；批次内部重复报错，提交时复检，禁止静默跳过或覆盖。
