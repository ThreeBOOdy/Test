# 学生账号注册、审核与批量导入设计

## 1. 背景与目标

现有 `User` 仅包含用户名、显示名称、密码、角色、启用状态和会话版本，尚未覆盖学生自主注册、实名资料、管理员审核、有效期和学生账号 Excel 导入。

本功能采用扩展统一 `User` 模型的方案，目标如下：

- 登录页提供学生注册入口。
- 自主注册后必须经管理员审核，审核通过前不能进入练习系统。
- 拒绝申请时必须填写原因，学生可以修改资料并重新提交。
- 管理员 Excel 导入的学生账号直接生效，无需再次审核。
- 普通账号默认有效一年，并支持管理员调整起止日期。
- 支持“长期账号”开关，开启后忽略日期限制，关闭后立即恢复日期判断。
- 到期、停用或关键账号状态变化后，现有会话在下一次请求时立即失效。
- 新增 `ADMIN` 角色，只有管理员可审核、管理学生账号、维护年级和导入学生账号。
- 身份证号和手机号严格校验、全局唯一、加密存储并按权限脱敏展示。
- Excel 支持预检、页面内编辑、重新校验和整批原子提交。

## 2. 非目标

- 不建立班级、院系、监护人或招生批次模型。
- 不允许审核通过的学生自行修改实名资料。
- 不物理删除已有学生及其练习记录。
- 不改变现有题库 Excel 的格式和教学权限。
- 不增加短信验证码、短信通知或邮件通知。

## 3. 核心业务决策

### 3.1 登录账号

- 学生使用独立 `username` 和密码登录。
- 用户名全局唯一，创建后永久不可修改。
- 身份证号和手机号属于实名资料，不作为登录账号。

### 3.2 两种创建方式

#### 学生自主注册

- 注册后账号状态为 `PENDING`。
- 学生可以用用户名和密码登录受限申请状态页。
- 管理员审核通过后才可进入练习系统。
- 默认有效期从审核通过日期开始计算一年。

#### 管理员 Excel 导入

- 仅管理员可以执行。
- Excel 每行填写初始密码。
- 导入成功后状态直接为 `ACTIVE`，无需再次审核。
- 默认有效期从导入成功日期开始计算一年。
- 学生首次登录必须修改初始密码。

### 3.3 拒绝与重新提交

- 管理员拒绝申请时必须填写拒绝原因。
- 被拒绝账号保留，不删除。
- 学生登录状态页后可查看拒绝原因并修改资料。
- 修改资料不自动重新提交；学生需要主动点击“重新提交审核”。
- 重新提交后状态恢复为 `PENDING`，当前拒绝原因清除，历史记录保留。

## 4. 数据模型

### 4.1 用户角色

扩展 `UserRole`：

- `STUDENT`：学生。
- `TEACHER`：普通教师，负责题库、知识点、规则和教学报表。
- `ADMIN`：管理员，负责学生账号、审核、年级配置和学生账号导入，同时可以访问教师教学功能。

现有种子用户名 `teacher` 升级为 `ADMIN`，另建普通教师示例账号。其他现有教师保持 `TEACHER`。

### 4.2 学生账号状态

新增 `StudentAccountStatus`：

- `PENDING`：等待审核。
- `ACTIVE`：审核通过或 Excel 导入后直接生效。
- `REJECTED`：审核被拒绝，可修改并重新提交。

不持久化 `EXPIRED`。是否过期根据当前时间、有效期和长期账号开关实时计算。

保留 `enabled` 作为独立停用开关：

- `enabled = false`：账号被管理员停用，不能建立完整或受限会话。
- `enabled = true` 不代表学生可进入练习系统，仍需检查审核状态和有效期。

### 4.3 注册来源

新增 `StudentRegistrationSource`：

- `SELF_REGISTRATION`
- `EXCEL_IMPORT`
- `LEGACY`：迁移前已有学生账号。

### 4.4 `User` 学生字段

在 `User` 上增加学生专用字段：

- `studentStatus`
- `registrationSource`
- `nationalIdEncrypted`
- `nationalIdHash`
- `nationalIdLast4`
- `gender`
- `school`
- `gradeId`
- `phoneEncrypted`
- `phoneHash`
- `phoneLast4`
- `submittedAt`
- `reviewedAt`
- `reviewedById`
- `rejectionReason`
- `validFrom`
- `validUntil`
- `isLongTerm`
- `profileIncomplete`：兼容缺少实名资料的历史学生。

教师和管理员的学生字段为空。服务端根据角色检查完整性，新注册和新导入学生必须拥有完整资料。

### 4.5 性别

- 根据居民身份证第 17 位顺序码自动计算。
- 注册、导入和编辑页面均只读展示。
- 身份证号变化后重新计算。
- API 不接受独立性别修改。

### 4.6 年级配置

新增 `Grade`：

- `id`
- `code`：稳定唯一代码。
- `name`：唯一显示名称。
- `sortOrder`
- `enabled`
- `createdAt`
- `updatedAt`

规则：

- 学校为必填自由文本，保存前去除首尾空格。
- 年级必须来自管理员维护的启用选项。
- 已被学生引用的年级不能删除，只能停用。
- 停用年级继续显示在已有学生资料中，但不能用于新注册、新导入或资料修改。
- Excel 优先按年级代码匹配，也兼容唯一年级名称。

### 4.7 审核历史

新增 `StudentReviewRecord`，至少记录：

- 学生 ID。
- 操作类型：提交、修改、重新提交、通过、拒绝。
- 操作人 ID。
- 操作时间。
- 操作前后状态。
- 拒绝原因。
- 当时资料的非敏感摘要。

现有 `AuditLog` 继续记录管理和安全操作。两类日志均不得记录密码明文、完整身份证号或完整手机号。

## 5. 敏感信息与校验

### 5.1 身份证号

- 仅支持中国大陆 18 位居民身份证。
- 严格校验出生日期、顺序码和校验码。
- 全局唯一。
- 存储认证加密后的完整值、带密钥 HMAC 和末四位。
- 普通列表展示为 `**************1234`。
- 管理员查看完整值时记录审计。
- `PENDING` 或 `REJECTED` 学生可在受限会话中编辑自己的完整值；普通只读状态页仍展示脱敏值。

### 5.2 手机号

- 使用中国大陆 11 位手机号严格校验。
- 全局唯一。
- 存储认证加密后的完整值、带密钥 HMAC 和末四位。
- 默认展示为 `138****5678`。
- 管理员查看完整值时记录审计。
- `PENDING` 或 `REJECTED` 学生可在受限会话中编辑自己的完整值；其他学生和普通教师不能读取完整值。

### 5.3 加密密钥

新增环境变量：

- `STUDENT_DATA_ENCRYPTION_KEY`
- `STUDENT_DATA_HASH_KEY`

要求：

- 启动时检查格式和长度。
- 生产环境缺少合法密钥时拒绝启动相关服务。
- 唯一性使用带密钥 HMAC，不使用普通 SHA-256。
- 完整值使用认证加密，能够检测密文篡改。
- 日志、错误响应、监控和审计元数据不得包含完整敏感值。

## 6. 有效期与长期账号

### 6.1 默认日期

- 自主注册：审核通过日到一年后的对应日期。
- Excel 导入：导入成功日到一年后的对应日期。
- 一年按业务时区的日历年计算，不固定增加 365 天。
- `2028-02-29` 的一年后日期定义为 `2029-02-28`。

### 6.2 日期边界

- 数据库存储 UTC 时间。
- 业务时区使用配置值，当前部署为 `Asia/Taipei`。
- 开始日期当天 `00:00:00` 生效。
- 结束日期当天 `23:59:59.999` 仍可使用。
- 非长期账号必须同时设置开始和结束时间，且结束时间晚于开始时间。

### 6.3 长期账号

- `isLongTerm = true` 时忽略有效期。
- 原日期继续保留。
- 关闭开关后立即恢复日期判断。
- 如果当前日期已超出有效期，关闭后账号立即不可使用。
- 长期账号仍受审核状态、停用状态和首次改密要求约束。

## 7. 统一会话能力

定义四类访问能力：

- `FULL_ADMIN`：管理员功能和教师教学功能。
- `FULL_TEACHER`：普通教师教学功能。
- `FULL_STUDENT`：已启用、`ACTIVE` 且有效期正常的学生。
- `REGISTRATION_ONLY`：已启用且为 `PENDING` 或 `REJECTED` 的学生。

每次读取会话及处理受保护请求时，以数据库当前数据为准检查：

1. 用户存在。
2. `enabled = true`。
3. JWT 中的 `sessionVersion` 与数据库一致。
4. 角色满足接口要求。
5. 学生状态满足能力要求。
6. 长期账号或当前时间位于有效期内。
7. 是否必须先修改密码。

审核状态和有效期不能只依赖 JWT 中的旧值。

以下操作必须增加 `sessionVersion`：

- 审核通过或拒绝。
- 停用或重新启用。
- 调整有效期。
- 开启或关闭长期账号。
- 修改实名资料。
- 重置密码。

因此，账号到期、停用或被管理员修改后，已有会话在下一次页面或 API 请求时立即失效。

## 8. 登录、注册和申请状态页

### 8.1 登录页

登录页保留用户名和密码，并增加“注册学生账号”。密码验证成功后分流：

- `ADMIN`：管理员控制台。
- `TEACHER`：教师控制台。
- 可用 `ACTIVE` 学生：练习系统。
- `PENDING`：建立受限会话并进入申请状态页。
- `REJECTED`：建立受限会话并进入申请状态页。
- 停用：不建立会话，提示联系管理员。
- 已过期：不建立会话，提示账号到期。
- 尚未开始：不建立会话，提示具体启用日期。

只有密码验证成功后才返回具体状态。用户名不存在或密码错误统一提示“用户名或密码错误”。

### 8.2 注册页

地址：`/register`。

字段：

- 用户名。
- 姓名。
- 身份证号。
- 性别，只读自动计算。
- 学校。
- 年级下拉选项。
- 手机号。
- 密码和确认密码。
- 信息真实性与隐私条款确认。

成功后：

- 创建 `STUDENT`。
- `studentStatus = PENDING`。
- `registrationSource = SELF_REGISTRATION`。
- `enabled = true`。
- 暂不设置有效期。
- `mustChangePassword = false`。
- 自动进入受限申请状态页。

### 8.3 申请状态页

地址：`/registration/status`。

#### 待审核

- 显示状态、提交时间、只读用户名、脱敏证件号和手机号及其他资料。
- 可修改姓名、身份证号、学校、年级和手机号。
- 用户名不可修改，性别自动更新。
- 修改后仍为 `PENDING`，并更新提交时间。

#### 已拒绝

- 显示拒绝原因、拒绝时间和审核人名称。
- 可以修改资料。
- 修改资料不自动改变状态。
- 主动重新提交后变为 `PENDING`，清除当前拒绝原因。

#### 审核通过

审核通过会增加 `sessionVersion`。学生旧受限会话下一次请求时失效，并被引导重新登录。

### 8.4 审核后的资料权限

- `ACTIVE` 学生不能自行修改姓名、身份证号、学校、年级或手机号。
- 学生只能修改自己的密码。
- 实名资料只能由管理员修改。

## 9. 管理员与教师信息架构

### 9.1 管理员区域

新增 `/admin`，至少包含：

- 管理概览。
- 注册审核。
- 学生账号。
- 学生账号 Excel 导入。
- 年级配置。
- 教师账号。
- 操作日志。

管理员还可以进入教师题库、知识点、规则、报表和题库导入功能。

### 9.2 普通教师区域

普通教师继续使用 `/teacher`。移除以下权限和导航：

- 学生账号管理。
- 注册审核。
- 学生账号 Excel 导入。
- 年级配置。

普通教师可查看教学报表必要的学生姓名、用户名、学校和年级，但不能查看完整身份证号、手机号或修改账号。

原 `/teacher/students` 迁移或重定向至 `/admin/students`。普通教师直接访问时返回无权限页面。

## 10. 管理员审核

### 10.1 审核列表

地址：`/admin/registrations`。

支持用户名、姓名、学校和手机号尾号搜索，年级和提交日期筛选，提交时间排序，单条审核和批量通过。

### 10.2 通过

- 默认开始日期为审核当天。
- 默认结束日期为开始日期一年后。
- 可调整起止日期或设为长期。
- 仅允许从 `PENDING` 更新为 `ACTIVE`。
- 写入审核人和审核时间，清除拒绝原因。
- 增加 `sessionVersion` 并记录审核历史和审计日志。
- 批量通过使用统一默认有效期；特殊账号单独处理。

### 10.3 拒绝

- 仅允许从 `PENDING` 更新为 `REJECTED`。
- 拒绝原因必填。
- 写入审核人和审核时间。
- 增加 `sessionVersion`。
- 不提供批量拒绝。

## 11. 学生账号管理

地址：`/admin/students`。

列表显示用户名、姓名、性别、学校、年级、脱敏证件号、脱敏手机号、注册来源、审核状态、计算后的可用状态、有效期、长期状态和创建时间。

管理员可以：

- 查看完整资料。
- 修改姓名、身份证号、学校、年级和手机号。
- 调整有效期。
- 开启或关闭长期账号。
- 停用或重新启用账号。
- 重置密码，并设置首次登录必须修改。
- 查看审核和操作记录。

用户名永久只读，身份证号变化后重新计算性别。系统不提供物理删除。

## 12. 学生账号 Excel 导入

### 12.1 权限

- 仅 `ADMIN` 可访问学生账号导入页面和 API。
- 学生账号导入与题库导入使用独立页面、模型和 API。
- 题库 Excel 导入继续允许 `ADMIN` 和 `TEACHER` 使用。

### 12.2 标准字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 用户名 | 是 | 全局唯一，创建后不可修改 |
| 姓名 | 是 | 去除首尾空格 |
| 身份证号 | 是 | 18 位严格校验，全局唯一 |
| 学校 | 是 | 自由填写 |
| 年级 | 是 | 匹配启用年级代码或唯一名称 |
| 手机号 | 是 | 中国大陆手机号严格校验，全局唯一 |
| 初始密码 | 是 | 满足统一密码强度 |
| 有效期开始日期 | 否 | 默认导入成功日期 |
| 有效期结束日期 | 否 | 默认开始日期一年后 |
| 长期账号 | 否 | 默认“否” |
| 是否启用 | 否 | 默认“是” |

性别不作为输入字段，由身份证号自动计算。

### 12.3 日期规则

- 支持 Excel 日期单元格和 `YYYY-MM-DD` 文本。
- 起止日期均为空时，提交时应用默认一年。
- 只填写开始日期时，结束日期自动为一年后。
- 只填写结束日期时视为错误。
- 非长期账号结束日期必须晚于开始日期。
- 长期账号可保留日期。
- 空白默认日期以最终提交时间为准，不使用预检时间。

### 12.4 预检和编辑

- 解析全部工作表，限制文件大小、工作表数量和总行数。
- 不执行公式或宏，仅安全读取缓存值或文本。
- 将结果保存为绑定当前管理员的临时草稿，建议 24 小时过期。
- 校验必填字段、格式、年级、密码、日期、文件内重复和数据库冲突。
- 所有输入字段可在预检表格中编辑。
- 身份证号变化后立即重新计算性别。
- 修改后标记为待重新校验。
- 支持单行校验和重新校验全部。
- 任意行有错误时不能提交。

### 12.5 整批原子提交

提交时服务端重新执行全部校验，并在单一事务中：

1. 再次检查用户名、身份证号和手机号冲突。
2. 创建全部学生账号。
3. 哈希全部初始密码。
4. 设置 `registrationSource = EXCEL_IMPORT`。
5. 设置 `studentStatus = ACTIVE`。
6. 设置 `mustChangePassword = true`。
7. 应用有效期、长期和启用设置。
8. 写入导入批次和审计记录。

任意一行失败时整批回滚。

### 12.6 密码和结果

- 初始密码在页面默认遮挡。
- 密码明文不得进入日志、审计或导入历史。
- 成功提交后立即删除草稿中的密码明文。
- 系统不提供初始密码回看或再次导出。
- 导入结果可下载不含身份证号、手机号和密码的清单。
- 所有导出文本防止以 `=、+、-、@` 开头造成公式注入。

## 13. API 边界

### 13.1 公共接口

- `POST /api/v1/auth/register`
- `GET /api/v1/grades/public`

注册接口限制请求体，并按 IP、用户名及敏感标识哈希实施频率限制。

### 13.2 申请接口

仅 `REGISTRATION_ONLY` 可访问：

- `GET /api/v1/registration`
- `PATCH /api/v1/registration`
- `POST /api/v1/registration/resubmit`

`PATCH` 只允许 `PENDING` 或 `REJECTED`，重新提交只允许 `REJECTED`。更新时使用 `updatedAt` 或版本号防止并发覆盖。

### 13.3 管理员审核接口

- `GET /api/v1/admin/registrations`
- `POST /api/v1/admin/registrations/:id/approve`
- `POST /api/v1/admin/registrations/:id/reject`
- `POST /api/v1/admin/registrations/bulk-approve`

全部强制检查 `ADMIN`，并使用当前状态作为条件更新。

### 13.4 管理员学生接口

- `GET /api/v1/admin/students`
- `GET /api/v1/admin/students/:id`
- `PATCH /api/v1/admin/students/:id`
- `POST /api/v1/admin/students/:id/reset-password`

不提供物理删除接口。

### 13.5 年级接口

- `GET /api/v1/admin/grades`
- `POST /api/v1/admin/grades`
- `PATCH /api/v1/admin/grades/:id`

### 13.6 学生导入接口

- `POST /api/v1/admin/student-imports/preview`
- `GET /api/v1/admin/student-imports/:id`
- `PATCH /api/v1/admin/student-imports/:id/rows/:rowId`
- `POST /api/v1/admin/student-imports/:id/validate`
- `POST /api/v1/admin/student-imports/:id/commit`

草稿绑定创建管理员；其他管理员不能直接读取其中的密码明文。

## 14. 错误代码与安全要求

稳定错误代码包括：

- `ACCOUNT_DISABLED`
- `ACCOUNT_EXPIRED`
- `ACCOUNT_NOT_YET_VALID`
- `REGISTRATION_PENDING`
- `REGISTRATION_REJECTED`
- `PASSWORD_CHANGE_REQUIRED`
- `SESSION_REVOKED`
- `REGISTRATION_CONFLICT`
- `STALE_ACCOUNT_STATE`
- `IMPORT_VALIDATION_FAILED`

安全要求：

- 密码验证前不公开账号状态。
- 所有写接口执行同源或 CSRF 检查。
- 登录、注册和重新提交应用频率限制。
- 用户名限制允许字符和长度。
- 所有请求体执行服务端 schema 校验和大小限制。
- 普通教师不能通过 API 读取完整身份证号或手机号。
- Excel 不执行宏或公式。
- 密码只保存哈希，接口不返回已有密码。
- 管理员重置密码时增加 `sessionVersion` 并设置 `mustChangePassword = true`。

## 15. 数据迁移

- 新增 `ADMIN` 枚举值。
- 种子用户名 `teacher` 升级为 `ADMIN`。
- 新增普通教师示例账号。
- 其他现有教师保持 `TEACHER`。
- 现有学生设为 `ACTIVE`、`LEGACY` 和 `isLongTerm = true`。
- 缺少身份证号、手机号、学校或年级的历史学生设为 `profileIncomplete = true`。
- 历史学生仍可登录和练习，由管理员逐步补全资料。
- 新注册和新导入学生不得缺失必填资料。
- 补全历史资料时执行严格格式和全局唯一校验。
- 保持现有用户 ID、练习记录、错题和成绩关联不变。
- 会话 payload 和角色校验扩展为接受 `ADMIN`。
- 原学生管理页面和 API 从教师权限迁移为管理员权限。

## 16. 并发与一致性

- 通过和拒绝只允许从 `PENDING` 发生。
- 重新提交只允许从 `REJECTED` 发生。
- 学生和管理员编辑时检查版本，避免覆盖并发操作。
- Excel 提交时重新校验唯一字段并使用事务。
- 唯一索引覆盖用户名、身份证 HMAC 和手机号 HMAC。
- 状态冲突返回 `STALE_ACCOUNT_STATE`，要求刷新后重试。

## 17. 测试与验收

### 17.1 领域测试

- 身份证校验和性别计算。
- 中国大陆手机号校验。
- 加密、解密、HMAC 和脱敏。
- 日历年有效期、闰日和日期边界。
- 长期、停用、到期和尚未生效判定。
- 状态流转、用户名不可修改和拒绝原因必填。
- 年级停用和引用规则。

### 17.2 API 测试

- 自主注册创建 `PENDING`。
- 重复用户名、身份证号和手机号被拒绝。
- 待审核和已拒绝学生只能访问申请接口。
- 待审核可修改资料且保持待审核。
- 被拒绝学生修改后主动重新提交。
- 审核通过默认生成一年有效期。
- 普通教师无法审核、管理或导入学生。
- 管理员可以访问教师教学接口。
- 到期、停用或账号变化后旧会话立即失效。
- 密码错误时不泄露账号状态。

### 17.3 Excel 测试

- 多工作表解析和页面编辑。
- 文件内重复和数据库冲突。
- 身份证、手机号、年级、密码和日期错误。
- 任意错误阻止整批提交。
- 任意一行失败时整批回滚。
- 导入账号直接 `ACTIVE`、默认一年并首次强制改密。
- 成功后不保留密码明文。
- 导出内容防公式注入。

### 17.4 端到端验收

1. 学生从登录页注册并进入待审核页。
2. 管理员拒绝，且拒绝原因必填。
3. 学生查看原因、修改资料并重新提交。
4. 管理员审核通过并生成一年有效期。
5. 学生旧受限会话失效，重新登录后进入练习系统。
6. 管理员停用账号，学生下一次请求立即退出。
7. 管理员设置过期日期后学生不能进入。
8. 开启长期账号后恢复使用，关闭后立即恢复过期判断。
9. 管理员上传 Excel、编辑错误、重新校验并原子导入。
10. 导入学生首次登录修改密码后进入练习系统。
11. 普通教师无法进入学生账号管理页面或接口。
12. 管理员仍可访问题库、规则、报表和题库 Excel 导入。

## 18. 完成标准

- 自主注册、审核、拒绝修改和重新提交流程闭环。
- Excel 导入支持字段编辑、整批校验和原子提交。
- 管理员与普通教师权限在页面和 API 两层隔离。
- 登录和全部学生 API 使用同一套有效期与账号可用性判定。
- 账号变化后旧会话在下一次请求时失效。
- 身份证号和手机号具备严格校验、唯一性、加密、脱敏和访问审计。
- 历史学生平滑迁移，不丢失练习数据，也不会因缺少新资料突然无法使用。
