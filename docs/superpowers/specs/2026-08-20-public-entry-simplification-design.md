# 首页/登录引导极简化改造规格

**日期：** 2026-08-20
**项目：** 智学练习（zhixue-practice）
**范围：** 公开入口视觉与信息架构收敛，不改变登录/角色路由/权限模型

## Problem Statement

当前首页是一套面向公开市场的营销落地页：包含双角色入口、特性介绍、频道卡片、数据统计、品牌粒子墙等大量内容；登录页也带有大图分栏、演示账号和“注册学生账号”按钮。产品实际定位是**机构报班学员使用的刷题软件**，现阶段不需要面向 C 端或 B 端做品牌营销。

用户打开网站时会被大量介绍文字和重复的登录引导干扰，找不到“直接开始刷题”的主路径。需要把公开入口收敛为极简的学生刷题入口，同时保留产品经理强调的注册审核流程，并让教师/管理员仍能通过统一登录表单按账号角色自动进入各自控制台。

## Solution

未登录用户访问网站时，看到一个一屏极简品牌页：Logo + 一句话 + “开始刷题”按钮；点击后进入统一的学员登录页。登录页只展示学生登录表单，但后端仍按账号角色自动路由：学生进入学生空间，教师进入教师控制台，管理员进入管理控制台。已登录用户再访问首页时直接重定向到各自角色首页。

公开登录页和注册页统一使用极简卡片视觉（Logo + 表单 + 轻量 Three.js 背景），移除大段介绍、双角色入口和营销区块。注册审核流程保留，登录页提供“注册学生账号”的文字入口。演示账号只在开发环境显示，测试账号密码统一为 `123456`，但真实用户的密码策略保持不变。

## User Stories

1. 作为机构报班学员，我想要打开网站时看到一个极简品牌页和唯一的“开始刷题”按钮，以便我不用阅读营销内容就能进入登录。
2. 作为机构报班学员，我想要点击“开始刷题”后直接进入学员登录页，以便尽快开始刷题。
3. 作为已有账号的学员，我想要在登录页输入用户名和密码后自动进入学生空间，以便直接看到练习入口和学习记录。
4. 作为教师，我想要通过同一个登录表单输入账号后自动进入教师控制台，以便继续管理题库和学生，而不需要在公开页看到教师入口。
5. 作为管理员，我想要通过同一个登录表单输入账号后自动进入管理控制台，以便处理注册审核和学生账号，而不需要在公开页看到管理员入口。
6. 作为已登录的学员，我想要访问首页时自动跳转到学生空间，以便不再看到登录引导。
7. 作为已登录的教师或管理员，我想要访问首页时自动跳转到各自控制台，以便快速回到工作区。
8. 作为尚未注册的报班学员，我想要在登录页看到“注册学生账号”入口，以便在线提交注册申请并等待审核。
9. 作为注册申请人，我想要注册页与登录页保持一致的极简视觉，以便公开入口体验统一、不显得割裂。
10. 作为产品经理，我想要注册审核流程完整保留，以便机构仍能通过审核管理学员报名。
11. 作为开发人员，我想要在开发环境看到测试账号（student/teacher/admin）且密码统一为 `123456`，以便快速自测登录和角色路由。
12. 作为安全负责人，我想要真实用户的密码策略不被放宽，以便 `123456` 只作为开发种子账号存在，不降低真实账号安全门槛。
13. 作为维护人员，我想要公开页不再展示教师/管理员入口卡片，以便产品定位聚焦在“机构学员刷题”。
14. 作为偏好减少动态效果的用户，我想要 Three.js 背景尊重 `prefers-reduced-motion`，以便不会因为特效感到不适。
15. 作为手机用户，我想要登录/注册页在窄屏下依然居中可用，以便随时随地登录刷题。
16. 作为测试人员，我想要端到端测试覆盖公开入口、登录跳转和已登录重定向，以便及时捕获回归。
17. 作为开发者，我想要种子初始化和本地重置脚本统一把测试账号密码写成 `123456`，以便本地与 CI 环境行为一致。
18. 作为未来的产品负责人，我想要统一登录表单和账号路由能力保持可扩展，以便未来拓展 to C / to B 时只需增加入口而不必重做认证。

## Implementation Decisions

- 首页改为“一屏品牌页”：Logo、主文案“波段研习 · 无线电考证智能刷题”、“开始刷题”按钮。按钮目标为登录页并携带学生目标路径，使学员登录后直接进入学生空间。
- 首页使用现有 Three.js 信号场组件的低密度模式作为整页轻背景，不新增 Three.js 特效；保留鼠标涟漪与减动效降级能力。
- 首页在服务端读取当前会话：已登录用户直接重定向到对应角色首页；未登录用户渲染品牌页。重定向目标按角色/capability 决定，注册中或待激活用户进入对应状态页。
- 公开登录页与注册页改用新的极简公开外壳：全屏居中卡片、Logo、标题、可选一句说明、表单区域、轻量背景。该外壳仅用于公开入口。
- 登录页标题为“学员登录”，注册页标题为“注册学生账号”。
- 登录表单保持统一：用户名 + 密码 + 提交；教师/管理员仍可通过同一表单登录。公开页不展示教师/管理员入口，但直接访问受保护路径或携带目标参数时仍可登录并自动路由。
- 登录页注册入口改为表单下方一行文字链接：“还没有账号？注册学生账号”。
- 注册页保留完整注册审核流程，只替换视觉外壳；注册页底部提供“已有账号？返回登录”链接。
- 登录表单新增一个“是否显示演示账号”的开关，仅在非生产环境显示演示账号；演示账号固定为 student / teacher / admin，密码均为 `123456`。
- 现有内部认证页（修改密码、激活账号）继续使用原认证外壳，不在本次改造范围内。
- 种子初始化默认密码改为 `123456`，保留 student / teacher / admin 三个测试账号。
- 新增本地开发库密码重置脚本，把 student / teacher / admin 三个账号密码重置为 `123456`；脚本直接写入密码哈希，不经过密码策略校验。
- 密码策略保持不变：学生密码至少 8 位，教师/管理员密码至少 12 位；`123456` 仅用于开发种子/重置，不代表真实用户可用的密码。
- 现有账号路由函数与各角色布局守卫保持不变；本次不引入 middleware，不改变权限模型。
- 生产环境的种子默认密码维持现状，避免弱密码默认进入生产；如需生产也统一为 `123456` 需另行决策。

## Testing Decisions

- 好的测试只验证外部可观察行为：用户看到什么、点击后去哪里、登录后进入哪个角色空间，而不是断言组件内部实现。
- 主要测试接缝为端到端测试（Playwright），覆盖：
  - 未登录访问首页时看到极简品牌页和“开始刷题”，且不出现教师/管理员入口。
  - 点击“开始刷题”进入登录页并携带学生目标路径。
  - 使用 student / teacher / admin 三个账号登录后分别进入学生空间、教师控制台、管理控制台。
  - 已登录用户访问首页时自动重定向到对应角色首页。
  - 登录页仍能看到“注册学生账号”入口。
- 现有静态内容测试同步更新，继续作为低成本回归接缝：
  - 公开页视觉接缝：登录/注册页使用新公开外壳，修改密码页仍使用原认证外壳。
  - 美术资源接缝：首页/登录页不再要求引用大图美术资源；内部页面仍保持原资源要求。
  - 首页结构接缝：首页包含信号场背景与“开始刷题”，不再要求双角色入口函数或教师入口。
- 登录表单的可读性测试保留，输入框样式类不变。
- 端到端测试中的登录选择器（用户名、密码、进入系统）保持不变，只更新测试账号密码为 `123456`。
- 先例：项目中已有 `core-visual-journeys`、`repository-quality` 等静态内容测试，以及多份 Playwright 登录/导航用例，可直接沿用。

## Out of Scope

- 不修改账号路由函数、登录 API、会话机制或角色权限模型。
- 不引入 middleware 统一鉴权。
- 不重做教师端、管理端、学生端内部页面。
- 不修改修改密码页与激活页的视觉。
- 不删除或弱化注册审核流程。
- 不修改密码策略。
- 不修改数据库 Schema。
- 不开发新的 Three.js 特效，只复用现有低密度信号场。
- 不实现 to C / to B 的未来扩展，只保留统一登录与路由的可扩展性。
- 不改变生产种子密码默认值（除非另行确认）。

## Further Notes

- 当前环境没有 `gh` CLI / GitHub Token，无法直接创建 GitHub Issue；本规格先落盘到项目规格文档目录，后续可手动粘贴到 Issue 跟踪。
- 登录/注册页使用新公开外壳后，原认证外壳仍保留给内部认证页，避免扩大改动范围。
- 端到端测试当前依赖“用户名”“密码”“进入系统”等稳定文案，本次改造会保留这些文案以降低测试维护成本。
- 测试账号密码统一为 `123456` 只影响开发种子与本地重置；真实用户注册/改密仍按密码策略执行。
